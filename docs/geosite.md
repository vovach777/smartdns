# geosite: готовые списки доменов в маршрутизации

`geosite:` — это правило маршрута, которое ссылается не на одно имя, а на
**набор доменов** из файла. Наборы берутся из публичных репозиториев
(Loyalsoldier/v2ray-rules-dat, v2fly, sing-box) в виде обычных текстовых
списков — по файлу на категорию.

> English version: [geosite.en.md](geosite.en.md)

---

## Быстрый старт

```yaml
geosite_dir: /etc/smartdns/geosite     # каталог с файлами <name>.txt

servers:
  upstream: 8.8.8.8
  blocked: refuse                       # заглушка: в сеть не ходит, сразу REFUSED

routes:
  - match: ["geosite:category-ads-all"]
    chain: [blocked]                    # первое совпадение выигрывает
  - match: ["geosite:cn"]
    chain: [local]
  - match: ["*"]
    chain: [upstream]
```

Файлы:

```
/etc/smartdns/geosite/cn.txt
/etc/smartdns/geosite/category-ads-all.txt
```

Имя набора = имя файла без `.txt`, то есть `geosite:cn` → `cn.txt`.

### Что в строках списка

| строка | что значит |
|---|---|
| `po.perco.ru` | сам домен **и все поддомены** |
| `domain:po.perco.ru` | то же самое |
| `full:exact.perco.ru` | **только** это имя, поддомены не входят |
| `*.po.perco.ru` | звёздочка снимается — то же, что `po.perco.ru` |
| `regexp:` / `keyword:` | не поддерживаются: в файлах из каталога — ошибка загрузки, в лениво скачанных — пропуск со счётчиком |

Регулярок и масок в списках нет — только «имя и поддомены» либо «точное имя».

## Формат списка

```
# комментарий
domain:example.com          # example.com и все поддомены
full:only.example.org       # ровно это имя, без поддоменов
plain.net                   # то же, что domain:plain.net
```

| строка | что значит |
|---|---|
| `#` | комментарий до конца строки |
| `full:name` | только точное совпадение |
| `domain:name` | имя и любые поддомены (по границе точки) |
| `name` без префикса | то же, что `domain:name` |
| пустые строки | игнорируются |

Сознательно **не поддерживаются**:

| директива | почему нет |
|---|---|
| `regexp:` | непредсказуемая стоимость на запрос; весь смысл матчера — сотни наносекунд |
| `keyword:` | то же плюс ложные срабатывания |
| `include:` | наборы и так складываются на уровне `routes` |

Встретили `regexp:` в файле — это **ошибка загрузки** с путём и номером строки,
а не тихий пропуск. Так лучше: иначе правило «иногда не срабатывает», и причину
не видно.

## Откуда брать списки

Категории лежат рядом с бинарными базами в тех же репозиториях — текстом:

| источник | путь в репозитории |
|---|---|
| Loyalsoldier/v2ray-rules-dat | `geosite/<category>.txt` (и `geoip/` для адресов) |
| v2fly/domain-list-community | `data/<category>` (формат тот же) |
| sing-box / SagerNet | `geosite.db` (бинарь) — для нас не годится, берите текстовые |

Кладите нужные категории в `geosite_dir` — целиком репозиторий не нужен.
Обновление — перезапись файлов; резолвер подхватит сам (см. ниже).

Лицензии и частота обновлений — на совести источника: это внешние данные,
резолвер их только читает.

---

## Как матчится

Имя приводится к нижнему регистру, хвостовая точка отбрасывается, затем
проверяются **суффиксы по границе точки**:

```
запрос: a.b.example.com
проверяем: a.b.example.com → b.example.com → example.com → com
```

- `domain:example.com` совпадёт с `a.b.example.com`, но **не** с `badexample.com`;
- `full:example.com` совпадёт только с `example.com`;
- порядок `routes` важен: первое подходящее правило выигрывает, поэтому
  `geosite:` ставьте выше общего `"*"`.

Стоимость: отсортированный срез суффиксов + бинарный поиск.
Замер на наборе 300 000 имён — **123 нс на запрос**, ~13 МБ кучи:

```
BenchmarkDomainSetMatch-24   19280059   123.3 ns/op
```

Для сравнения: попадание в кэш — единицы микросекунд, запрос к апстриму —
1–50 мс. Матчер не виден на этом фоне.

## Обновление без рестарта

| способ | поведение |
|---|---|
| автоматически | раз в 5 с проверяются mtime/size файлов в `geosite_dir`; при изменении конфиг перечитывается, кэш сбрасывается |
| `SIGHUP` | то же вручную и сразу |
| рестарт | только при правке YAML (например, нового `geosite:` в `routes`) |

Правка YAML требует перечитывания конфига: `systemctl reload smartdns`.

## Проверка и диагностика

```bash
smartdns -check -config smartdns.yaml
```

```
geosite: 1 наборов из /etc/smartdns/geosite
  cn                             /etc/smartdns/geosite/cn.txt    41233 записей

цепочки (первое совпадение выигрывает):
  geosite:cn                     -> local
  *                              -> upstream
```

Имя не попало в набор — по порядку:

1. `-check` печатает набор? Если нет — файл не в `geosite_dir` или не `.txt`;
2. `domain:` против `full:` — поддомены совпадают только с `domain:`;
3. правило `geosite:` стоит **выше** общего `"*"`? Иначе до него не дойдёт;
4. граница точки: `domain:example.com` не ловит `badexample.com`;
5. в логе есть ошибка разбора файла — набор не загрузился целиком, старый
   конфиг продолжает работать.

## Что пока не сделано

- **`geoip:`** (наборы адресов, CIDR) — отдельная задача: матчить нужно ответ,
  а не имя запроса, это другой поток принятия решения;
- **автозагрузка** списков из сети — сознательно нет: резолвер не должен ходить
  в интернет за правилами сам;
- **`regexp:`** — см. выше.
