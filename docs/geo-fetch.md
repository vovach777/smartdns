# Наборы по URL: ленивая загрузка и обновление в полночь

Наборы `geosite:`/`geoip:` можно не раскладывать по диску руками — резолвер
скачает их сам, когда они понадобятся, и обновит раз в сутки.

> English version: [geo-fetch.en.md](geo-fetch.en.md)

---

## Источники: два режима

Режим определяется тем, есть ли в URL `{name}`.

**1. Единый `.dat` (по умолчанию)** — формат v2ray, российские базы
[runetfreedom/russia-v2ray-rules-dat](https://github.com/runetfreedom/russia-v2ray-rules-dat):
в ветке `release` всегда лежит последняя версия.

```yaml
geosite_url: https://raw.githubusercontent.com/runetfreedom/russia-v2ray-rules-dat/release/geosite.dat
geoip_url:   https://raw.githubusercontent.com/runetfreedom/russia-v2ray-rules-dat/release/geoip.dat
```

Файл качается целиком (geosite.dat ≈ 70 МБ, geoip.dat ≈ 18 МБ), кэшируется как
`<geo_cache_dir>/geosite.dat` / `geoip.dat`; по умолчанию `geo_cache_dir` —
`/tmp/smartdns`, так что после перезагрузки базы просто скачаются заново. В памяти остаются **только**
категории, упомянутые в правилах: файл разбирается одним проходом, остальные
1000+ категорий выбрасываются.

Имена категорий в базе — в верхнем регистре (`CATEGORY-ADS-ALL`, `RU`), в
правилах регистр не важен: `geosite:category-ads-all` и `geosite:RU` работают.

**2. По имени (`{name}` в URL)** — текстовые списки v2fly/ipdeny, по файлу на
набор:

```yaml
geosite_url: https://raw.githubusercontent.com/v2fly/domain-list-community/master/data/{name}
geoip_url:   https://www.ipdeny.com/ipblocks/data/aggregated/{name}-aggregated.zone
```

`{name}` — имя набора из правила (`geosite:category-ads-all` →
`category-ads-all`). Кэш: `<geo_cache_dir>/geosite/<name>.txt` и
`<geo_cache_dir>/geoip/<name>.txt`.

**Формат выбирается по содержимому файла, а не по расширению:** если в первых
байтах есть управляющие символы — это protobuf (`.dat`), иначе текст. Поэтому
`https://…/{name}.dat` (одна категория на файл) тоже работает; расширение роли
не играет.

---

## Как это работает

1. **Лениво.** Набор качается при первом обращении правила к нему (на старте
   запускаются только те, что реально упомянуты в `routes` / `answer_geoip`).
2. **Не блокирует DNS.** Загрузка идёт в горутине. Пока набора нет, правило
   просто не совпадает — запрос уходит по общему `"*"`. Следующие запросы
   увидят набор.
3. **Кэш на диске.** Запись атомарная (tmp + rename). Если файл уже в кэше,
   он применяется сразу (работает без сети), а свежая версия подтягивается
   следом. Недокачанные `*.tmp` старше часа вычищаются при первом обращении.
4. **Появление набора сбрасывает DNS-кэш.** Иначе домен, ответившийся по
   общему `"*"` пока набор качался, жил бы в кэше ещё весь TTL.
5. **Таймауты под размер файла:** соединение 15 с, тело — до 10 минут.
   Ответы 404/403/410 запоминаются до перезапуска; после сетевого сбоя —
   пауза в минуту, чтобы запросы не дёргали сеть каждый раз.
6. **`include: разворачивается`** (режим `{name}`). Списки v2fly — дерево
   `include:`, атрибуты (`name @ads`) отрезаются: фильтровать по атрибутам мы
   не умеем, берём запись целиком. Родитель пересобирается, когда приезжает
   включённый набор.
7. **Обновление в 00:00** локального времени: единый `.dat` перекачивается
   целиком и нужные категории разбираются заново; в режиме `{name}`
   перекачиваются только уже загруженные наборы.

---

## Чего нет

- нет автозагрузки **всех** категорий — только тех, что упомянуты в правилах;
- атрибуты (`@ads`, `@cn`) не фильтруются;
- `regexp:`-записи из баз пропускаются и считаются (видны в `-check`);
- IPv6-диапазоны из `geoip.dat` пропускаются (счётчик в `-check`): в правилах
  `geoip:` сейчас только IPv4;
- при обновлении в полночь файлы перезаписываются, истории версий нет.

## Диагностика

```
гео-наборы: лениво по URL, кэш /tmp/smartdns
  домены: https://…/geosite.dat (единый .dat)
  адреса: https://…/geoip.dat (единый .dat)
  обновление: ежедневно в 00:00
```

В логе:

```
гео: geosite.dat — применено категорий: 1 из 1 запрошенных
гео: geoip — загрузка не удалась: HTTP 404 …
гео: полночь — обновляю загруженные наборы
гео: geosite.dat — обновлён
```

Если правило «не срабатывает» сразу после старта — это ожидаемо: набор ещё
качается (70 МБ на медленном канале — это минуты). Проверить, что он появился:
`ls -lh <geo_cache_dir>/`.
