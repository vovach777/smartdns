# Наборы по URL: ленивая загрузка и обновление в полночь

Наборы `geosite:`/`geoip:` можно не раскладывать по диску руками — резолвер
скачает их сам, когда они понадобятся, и обновит раз в сутки.

> English version: [geo-fetch.en.md](geo-fetch.en.md)

---

## Конфиг

```yaml
geo_cache_dir: /var/cache/smartdns      # куда складывать (по умолчанию так)
geosite_url: https://raw.githubusercontent.com/v2fly/domain-list-community/master/data/{name}
geoip_url:   https://www.ipdeny.com/ipblocks/data/aggregated/{name}-aggregated.zone
```

`{name}` — имя набора из правила (`geosite:category-ads-all` → `category-ads-all`).
Оба URL по умолчанию уже прописаны; указывать их нужно только чтобы сменить
источник (свой зеркал, локальный сервер, другая ветка).

---

## Как это работает

1. **Лениво.** Набор качается при первом обращении правила к нему (на старте
   запускаются только те, что реально упомянуты в `routes` / `answer_geoip`).
2. **Не блокирует DNS.** Загрузка идёт в горутине. Пока набора нет, правило
   просто не совпадает — запрос уходит по общему `"*"`. Следующие запросы
   увидят набор.
3. **Кэш на диске.** `<geo_cache_dir>/geosite/<name>.txt` и
   `<geo_cache_dir>/geoip/<name>.txt`, запись атомарная (tmp + rename).
   Есть кэш — работает и без сети.
4. **include: разворачивается.** Списки v2fly — дерево `include:`, атрибуты
   (`name @ads`) отрезаются: фильтровать по атрибутам мы не умеем, берём
   запись целиком. Родитель пересобирается, когда приезжает включённый набор.
5. **Обновление в 00:00** локального времени: перекачиваются только уже
   загруженные наборы, затем конфиг перечитывается.

---

## Чего нет

- нет автозагрузки **всех** наборов из репозитория — только тех, что упомянуты;
- атрибуты v2fly (`@ads`, `@cn`) не фильтруются;
- `regexp:`/`keyword:` из списков пропускаются и считаются (видны в `-check`);
- при обновлении в полночь старые файлы перезаписываются, истории версий нет;
- 404 и прочие отказы запоминаются до перезапуска: одно и то же имя не
  дёргается каждую секунду.

---

## Диагностика

```
гео-наборы: лениво по URL, кэш /var/cache/smartdns
  домены: https://…/{name}
  адреса: https://…/{name}-aggregated.zone
  обновление: ежедневно в 00:00
```

В логе:

```
гео: geosite:category-ads-all загружен по URL и применён
гео: geosite:zhihu — загрузка не удалась: HTTP 404 …
гео: полночь — обновляю загруженные наборы
```

Если правило «не срабатывает» сразу после старта — это ожидаемо: набор ещё
качается. Проверить, что он появился: `ls <geo_cache_dir>/geosite/`.
