# Записи из файлов hosts

Резолвер умеет отдавать ответы из файлов формата `/etc/hosts` — тех же самых,
что читает система. Это нужно, когда одна и та же запись должна работать на
нескольких машинах, а копировать её руками по всем `/etc/hosts` не хочется.

Классическая причина: имя есть в `/etc/hosts` на хосте сборки, но **в контейнер
оно не попадает** — Docker каждому контейнеру генерирует собственный
`/etc/hosts`. Если резолвер читает тот же файл и отвечает по сети, запись
становится общей, а правится одним `append`.

> English version: [hosts.en.md](hosts.en.md)

---

## Быстрый старт

```yaml
hosts_files:
  - /etc/hosts          # обычный файл
  - /etc/hosts.d        # каталог: все файлы внутри, по алфавиту
```

Перезапуск не нужен: изменения в файле подхватываются за ~5 секунд
(см. [Обновление](#обновление)).

Проверить, что конфиг понят:

```bash
smartdns -check -config smartdns.yaml
```

```
hosts_files: 1 из конфига, 3 из файлов
  /etc/hosts                             3 записей, перекрыто 1
```

## Формат файла

Обычный `/etc/hosts`:

```
# комментарий
172.17.0.77   serv_das.po.perco.ru  serv-das
10.0.0.7      my.local.test
::1           v6.local.test
```

Правила разбора:

| Что | Как понимается |
|---|---|
| `#` | начало комментария, до конца строки |
| пустые строки | игнорируются |
| первое поле | адрес IPv4 или IPv6 (`net.ParseIP`) |
| остальные поля | имена; каждое получает этот адрес, алиасы работают |
| хвостовая точка | отбрасывается (`my.local.` → `my.local`) |
| регистр | приводится к нижнему — DNS регистронезависим |
| мусор в первом поле | **ошибка с путём и номером строки**, файл не применяется частично |

Пример ошибки:

```
smartdns: /etc/hosts.d/lab:3: не адрес: "10.0.0."
```

Так сделано намеренно: тихо пропущенная строка в hosts — это имя, которое
«иногда не резолвится», и такая диагностика дороже, чем явная ошибка на старте.

## Приоритет и слияние

```
hosts:            (YAML)   ← главнее всего
  ↓
hosts_files: [файл1, файл2, каталог/…]
  ↓
первое вхождение имени выигрывает
```

- запись из секции `hosts:` **всегда** перекрывает файловую: локальная подмена
  не зависит от того, что кто-то дописал в `/etc/hosts`;
- внутри файлов и между файлами действует правило «первый победил» — как в
  классическом `/etc/hosts`;
- перекрытые записи не теряются молча: в `-check` видно `перекрыто N`, а в
  логе при старте — сколько записей пришло из конфига и сколько из файлов.

Пример: в конфиге `keep.example: 10.9.9.9`, в файле `keep.example 10.1.1.1` →
отвечать будет `10.9.9.9`, файловая запись попадёт в `перекрыто`.

## Обновление

| Способ | Когда срабатывает |
|---|---|
| автоматически | раз в **5 секунд** сравниваются `mtime` и `size` каждого файла; при расхождении конфиг перечитывается и кэш сбрасывается |
| вручную | `SIGHUP` (`systemctl reload smartdns`) — то же самое, немедленно |
| рестарт | нужен только при изменении самого YAML |

Что важно знать про автоперечитывание:

- перечитывается **конфиг целиком**, а не только hosts; кэш при этом
  сбрасывается — следующий запрос пойдёт к апстриму;
- список файлов пересчитывается заново: если в каталоге появился новый файл, он
  подхватится;
- если в новом состоянии файл содержит ошибку, перечитывание не применится, в
  логе будет причина, продолжит работать предыдущая версия;
- удаление файла из списка (правка YAML) требует `SIGHUP` или рестарта.

## Каталоги

Каталог читается **не рекурсивно**: берутся все обычные файлы внутри, в
алфавитном порядке. Подкаталоги игнорируются. Удобно для деплоя: сервис кладёт
свой файл в `/etc/hosts.d/50-service`, ничего не редактируя в общем.

Порядок алфавитный — значит `10-…` перекрывает `20-…` (первый победил).

## Чего файлы не умеют

`hosts:` в YAML умеет больше, файл — только «адрес → имя»:

| Возможность | `hosts:` (YAML) | файл hosts |
|---|---|---|
| IPv4 / IPv6 | да | да |
| несколько адресов через запятую | да | нет (только один на строку) |
| `"*.domain"` (суффикс) | да | **нет** |
| `nxdomain` / `refused` (блокировка) | да | **нет** |
| CNAME (значение — домен) | да | **нет** |

Если нужна блокировка или шаблон — это в `hosts:`, файлы для простых пар
«адрес-имя».

## Проверка и диагностика

```bash
# как конфиг понят (ничего не запускает)
smartdns -check -config smartdns.yaml

# что реально отвечает
dig @127.0.0.1 serv_das.po.perco.ru A +short
dig @127.0.0.1 my.local.test A +short
dig @127.0.0.1 v6.local.test AAAA +short
```

Если имя не резолвится — по порядку:

1. `-check` показывает файл в списке? Если нет — ключ не тот или путь не тот;
2. у файла есть `перекрыто N` — значит имя задано раньше (в YAML или в файле,
   который идёт первым);
3. файл читается пользователем, под которым работает сервис (права `644` и
   доступ к каталогу; для systemd-юнита с `User=` это не всегда `root`);
4. имя в запросе и в файле совпадает по буквам (регистр не важен, а вот дефис
   против подчёркивания — важен);
5. `SIGHUP` не помог и в логе есть ошибка разбора — файл не применился целиком.

## Пример: имя для сборки в контейнере

Задача: `serv_das.po.perco.ru` должен резолвиться и на хосте, и внутри
контейнеров, где своего `/etc/hosts` нет.

```yaml
# smartdns.yaml на хосте сборки
listen: 172.17.0.133:53
servers:
  resolved: 127.0.0.53:53
routes:
  - match: ["*"]
    chain: [resolved]
hosts_files:
  - /etc/hosts        # там уже есть строка 172.17.0.77 serv_das.po.perco.ru
```

```yaml
# docker/compose.yml — контейнер спрашивает этот резолвер
services:
  sdk:
    dns: ["172.17.0.133"]
```

Дальше любая правка `/etc/hosts` на хосте видна в контейнере через ~5 секунд,
без `extra_hosts`, без перезапуска контейнера и без правки DNS-зоны.
