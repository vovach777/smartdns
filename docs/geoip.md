# geoip: фильтр ответа по адресным наборам

`geoip:` в этом резолвере — **не** правило маршрутизации. Маршрут выбирается по
имени до запроса, а адрес появляется только в ответе. Поэтому здесь это
**фильтр готового ответа**: он смотрит на адреса в ответе и может переписать
результат (`nxdomain` / `refused` / пустой `noerror`).

Главное свойство: фильтр ничего не спрашивает заново. Ответ фильтруется один
раз и в таком виде попадает в кэш, поэтому зациклиться и «спросить ещё разок»
нечему.

> English version: [geoip.en.md](geoip.en.md)

---

## Быстрый старт

```yaml
geoip_dir: /etc/smartdns/geoip

answer_geoip:
  - set: blocked          # файл /etc/smartdns/geoip/blocked.txt
    action: nxdomain      # nxdomain | refused | noerror
```

`blocked.txt`:

```
# по строке на префикс или адрес
203.0.113.0/24
198.51.100.7
# IPv6-строки пропускаются и считаются отдельно
2001:db8::/32
```

Ответ, в котором есть адрес из набора, переписывается:

| action | что видит клиент |
|---|---|
| `nxdomain` | `NXDOMAIN`, записи выброшены |
| `refused` | `REFUSED`, записи выброшены |
| `noerror` (или пусто) | пустой `NOERROR` — «имени нет», но без NXDOMAIN |

---

## Почему фильтр, а не маршрут

Три возможных места для решения по адресу:

| где | можно ли | итог |
|---|---|---|
| по имени (geosite) | да | выбираем цепочку до запроса — текущее поведение |
| по адресу ответа, меняя цепочку | **опасно** | пришлось бы резолвить заново → цикл, повторные запросы, нестабильный кэш |
| по адресу ответа, переписывая ответ | **да** | один запрос, детерминированный результат, кэш хранит уже отфильтрованное |

Мы делаем третье. Отсюда гарантия: **один запрос — один ответ**, без повторов.

Проверка на живой сборке:

```
1-й запрос github.com  → ГЕО ... отфильтровано → NXDOMAIN   (сходил к апстриму)
2-й запрос github.com  → КЭШ              → NXDOMAIN   (апстрим не спрашивали)
```

---

## Формат набора

| строка | смысл |
|---|---|
| `10.0.0.0/8` | CIDR |
| `203.0.113.7` | одиночный адрес |
| `# …` | комментарий |
| IPv6 (`2001:db8::/32`) | **пропускается**, счётчик виден в `-check` |

Пересекающиеся и смежные диапазоны сливаются при загрузке — поиск идёт
бинарём по отсортированным диапазонам, порядка сотни наносекунд на адрес.

Мусор в строке — ошибка загрузки с путём и номером строки.

## Проверка

```bash
smartdns -check -config smartdns.yaml
```

```
geoip: 1 наборов из /etc/smartdns/geoip
  blocked              /tmp/gip/geoip/blocked.txt               1 префиксов
  фильтр ответа: geoip:blocked -> nxdomain
```

## Обновление

Тот же вотчер, что у `hosts_files` и `geosite`: раз в 5 секунд сравниваются
mtime/size файлов в `geoip_dir`, при изменении конфиг перечитывается и кэш
сбрасывается. `SIGHUP` — то же вручную.

Важно: после сброса кэша первые ответы снова пойдут к апстриму — это ожидаемо,
фильтр применится к ним заново.

---

## Ограничения

- только IPv4;
- фильтр не влияет на маршрут: «сходить в другую цепочку, если адрес не тот» —
  сознательно не сделано;
- нет автозагрузки списков из сети;
- `answer_geoip` работает по `A`-записям (`AAAA` вырезается отдельным правилом,
  если `ipv6: false`).
